# Wi-Fi Profile Installer

A PowerShell automation tool that installs Windows Wi-Fi profiles and configures them to automatically connect when the configured wireless networks are available.

This project is designed as a small Windows administration/automation project and portfolio example.

## Features

- Installs multiple Wi-Fi profiles in one run
- Configures profiles for automatic connection
- Supports WPA2-Personal (WPA2-PSK/AES)
- Uses Windows' built-in `netsh wlan` tooling
- XML-escapes SSIDs and passwords before placing them in WLAN profile XML
- Creates and removes temporary profile files automatically
- Validates that the script is being run with Administrator privileges
- Displays the installed Wi-Fi profiles after completion

## Requirements

- Windows 10 or Windows 11
- PowerShell 5.1+ or PowerShell 7+
- Administrator privileges
- Wi-Fi networks using WPA2-Personal / WPA2-PSK with AES

## Quick Start

1. Download or clone this repository.
2. Open `Install-WiFiProfiles.ps1`.
3. Replace the example SSID and password values with your own networks.
4. Open PowerShell **as Administrator**.
5. Run:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\Install-WiFiProfiles.ps1
```

The script will add each profile and configure Windows to connect automatically when the network is available.

## Example Configuration

```powershell
$wifiNetworks = @(
    @{
        SSID     = "Home-WiFi"
        Password = "YOUR-PASSWORD-HERE"
    },
    @{
        SSID     = "Office-WiFi"
        Password = "YOUR-PASSWORD-HERE"
    }
)
```

An example configuration is included in `examples/networks.example.ps1`.

## How It Works

The script follows this workflow:

1. Reads the configured SSID/password pairs.
2. Escapes XML-sensitive characters.
3. Generates a temporary Windows WLAN profile XML document.
4. Sets `connectionMode` to `auto`.
5. Imports the profile with:

```powershell
netsh wlan add profile filename="..." user=all
```

6. Deletes the temporary XML file.
7. Displays the Wi-Fi profiles currently installed on the computer.

The profile XML uses the Windows WLAN profile schema:

```text
http://www.microsoft.com/networking/WLAN/profile/v1
```

## Security Considerations

**Do not commit real Wi-Fi passwords to a public repository.**

The WLAN XML generated by this project uses:

```xml
<protected>false</protected>
```

This is intentional for compatibility with the profile import process, but it means the password is present in the temporary XML in readable form while the script is running.

The script deletes the temporary XML file after each profile is imported. However, this project should still be treated as credential-handling software.

For real-world deployments, consider using an enterprise Wi-Fi authentication method, device-management tooling, or another credential-management approach instead of storing passwords directly in scripts.

## Supported Authentication

The current XML template is designed for:

- WPA2-Personal
- WPA2-PSK
- AES/CCMP encryption

Enterprise Wi-Fi, WPA3-specific configurations, certificates, 802.1X, and other authentication methods may require different WLAN profile XML.

## Troubleshooting

### "Access is denied"

Run PowerShell as Administrator.

### The device does not automatically connect

Verify that:

- The SSID is correct.
- The password is correct.
- The network uses a supported authentication configuration.
- The profile appears under:

```powershell
netsh wlan show profiles
```

You can inspect the current Wi-Fi interface with:

```powershell
netsh wlan show interfaces
```

### A profile already exists

Windows may report that a profile with the same name already exists. You can inspect or remove an existing profile with:

```powershell
netsh wlan show profiles
netsh wlan delete profile name="YOUR-SSID"
```

Then run the installer again.
